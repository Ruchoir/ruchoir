# Building the phone apps

The phone apps run as a **development build**: Ruchoir itself with Expo's development launcher
(`expo-dev-client`), which opens the JavaScript from a Metro server, the way Expo Go did. JavaScript
changes reach the phone through Metro as before; a new build is needed only when something native
changes (a native library added or upgraded, `app.config.ts`, an Expo SDK upgrade).

Builds are made by GitHub Actions (`.github/workflows/mobile-build.yml`), on GitHub's macOS runner for
the iPhone and its Linux runner for Android, free for a public repository (ADR 0005). Nothing of
Expo's hosted services is used.

```
iPhone:   macOS runner: prebuild, archive, Apple signs at export ─▶ App Store Connect ─▶ TestFlight
Android:  Linux runner: prebuild, debug APK ─▶ artifact of the run ─▶ an emulator
```

## Starting a build

Either:

- **Actions** tab, **Phone apps**, **Run workflow**: pick the branch and `both`, `ios` or `android`;
- or the label **`app-build`** on a pull request of this repository: both apps are built from the
  pull request's branch, once. To build again, remove the label and add it back, or use the button.

Builds never run on their own. A pull request from a fork is never built (GitHub gives it no
secrets).

The native folders (`apps/mobile/ios`, `apps/mobile/android`) are generated by `expo prebuild` in the
job and never committed: anything native is said in `app.config.ts` or a config plugin.

The build number Apple and Google see is the workflow's run number (`RUCHOIR_BUILD_NUMBER`, read by
`app.config.ts`), so every run is above the last. Re-running a run whose upload succeeded is refused by
App Store Connect (same number): start a new run instead.

## iPhone

The job archives the app **unsigned**, signs it ad hoc (which keeps its entitlements), then
`xcodebuild -exportArchive` signs it for the App Store and uploads it in the same step. Signing goes
through Xcode's cloud signing with the App Store Connect API key: Apple creates and keeps the
distribution certificate, so no certificate or profile is stored anywhere. The archive is unsigned
because Xcode's automatic signing would first ask for a development profile, which Apple only makes
for a team with a registered device.

The build is marked for **internal testing only**: members of the Apple team install it from
TestFlight, with no Beta App Review. App Store Connect takes 10 to 30 minutes to process it, then
e-mails the account holder; TestFlight keeps a build 90 days.

### Secrets

Repository secrets (Settings, Secrets and variables, Actions), set by the account holder:

| Secret | What |
|---|---|
| `APPLE_TEAM_ID` | the team ID (developer.apple.com, membership details) |
| `APPLE_API_KEY_ID` | the key's ID |
| `APPLE_API_ISSUER_ID` | the issuer ID shown above the keys |
| `APPLE_API_KEY_P8` | the whole text of the `.p8` file, `BEGIN` and `END` lines included |

The key is a **team key with the Admin role** (App Store Connect, Users and Access, Integrations, App
Store Connect API): an individual key cannot reach the provisioning endpoints that cloud signing uses.
The `.p8` downloads only once, and Safari on an iPhone fails to download it: do it from a computer.
The job writes it to the runner's temporary folder and deletes it at the end, even after a failure.

**Replacing the key** (lost, leaked, or someone left): revoke it in App Store Connect, create a new
team key with the Admin role, and replace `APPLE_API_KEY_ID` and `APPLE_API_KEY_P8`. Nothing else
changes: the distribution certificate belongs to the team, not to the key.

### Installing

1. TestFlight on the iPhone (Apple's app, from the App Store), signed in with an Apple account that is
   a member of the team in App Store Connect.
2. Once App Store Connect has processed the build, it appears in TestFlight: **Install**.
3. Open Ruchoir: the development launcher asks for a server. Enter Metro's address (the development
   host, `https://...`), or pick it from the recent ones.

## Android

The job builds a debug APK for `arm64-v8a` and `x86_64` (an emulator on an Apple Silicon Mac or on a
PC), signed with the debug key, and keeps it 14 days as the run's artifact
`ruchoir-dev-android-<run>`.

1. Android Studio, with a recent Pixel emulator (API 36).
2. From the run's page on GitHub, download the artifact (a zip) and unzip it.
3. Drop `app-debug.apk` on the running emulator, or `adb install app-debug.apk`.
4. Open Ruchoir and enter Metro's address in the launcher.

An emulator neither vibrates nor has real biometrics or notifications: check those on a real phone
before a store release.

## When a build fails

- **iPhone, "No Accounts" or a provisioning error at export:** the key is not a team key with the
  Admin role, or a secret holds something else (an extra space, a missing line of the `.p8`).
- **iPhone, "bundle version must be higher":** a run was re-run after its upload; start a new run.
- **App Store Connect e-mails "ITMS-91053: Missing API declaration":** a library uses one of Apple's
  "required reason" APIs without declaring it. React Native gathers every library's own privacy
  manifest at `pod install`; add what the e-mail names to `ios.privacyManifests` in `app.config.ts`.
- **Android, Gradle runs out of memory:** raise `org.gradle.jvmargs` through a config plugin, not by
  editing the generated `android/` folder.
